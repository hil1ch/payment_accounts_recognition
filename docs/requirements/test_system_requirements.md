# Тестирование требования к системе

## 1. Тестирование функциональных требований (общие)

- **FR-SYS-01:** Приём PDF-скана платёжного счёта через интерфейс Telegram-бота.
  #### Цель: проверить, что бот принимает PDF.
  #### Данные: набор PDF: корректный платёжный счёт, файл другого типа (.jpg, .txt), очень большой файл.
  #### Как тестировать:
  #### 1. Отправить в чат бота корректный PDF
  #### 2. Отправить файл другого типа
  #### 3. Отправить очень большой файл PDF
  #### Ожидаемый результат:
  #### Для корретных PDF бот отвечает подтверждением приёма
  #### Для файлов других типов и слишком больших объемов отправляет соотвествующую фразу
  #### Автоматизация тестирования: python-telegram-bot + pytest
- **FR-SYS-02:** Обработка загруженного PDF и возврат JSON с распознанной структурой документа.  
  #### Цель: проверить, что сервер возвращает валидный JSON с распознанными полями.
  #### Данные: корректный PDF-файл
  #### Как тестировать:
  #### 1. Отправить корректный PDF-файл
  #### 2. Проверить, что тело ответа - валидный JSON
  #### Ожидаемый результат:
  #### Сервер возвразает тело ответа валидный JSON
  #### Автоматизация тестирования: pytest + requests
- **FR-SYS-03:** При невозможности распознать значение поля — в JSON записывается заранее установленное спец-слово (например `"UNKNOWN_VALUE"`).  
  #### Цель: проверить, что при неопределённости значение заменяется на спецслово.
  #### Данные: PDF в которых поля удалены или замазаны.
  #### Как тестировать:
  #### Отправить PDF с удаллеными или замазаными полями.
  #### Ожидаемый результат:
  #### В JSON на полях присутствуют спецслова `"UNKNOWN_VALUE"`.
  #### Автоматизация тестирования: pytest + requests
- **FR-SYS-04:** Если невозможно распознать наименование поля — в JSON поле не записывается.  
  #### Цель: проверить, что отсутствующие имена полей не попадают в JSON.
  #### Данные: PDF в которых поля невозможно распознать наименование поля
  #### Как тестировать:
  #### Отправить PDF у которого невозможно распознать наименование поля.
  #### Ожидаемый результат:
  #### Отсутствие полей в JSON для которых нет распознанного имени.
  #### Автоматизация тестирования: pytest + requests
- **FR-SYS-05:** Бот отправляет пользователю текст с отформатированным JSON при ответе сервера `2xx`.  
  #### Цель: бот отправляет текст при ответе 2хх
  #### Данные: корректный PDF
  #### Как тестировать:
  #### 1. Отправка корректного PDF
  #### 2. Получение текста с отформатированным JSON от бота при ответе 2хх
  #### Ожидаемый результат:
  #### Ответ сервера 2хх, JSON валиден
  #### Автоматизация тестирования: pytest + requests
- **FR-SYS-06:** Бот отправляет спецфразу при ответе сервера `5xx`.
  #### Цель: убедиться, что при сбое сервера бот сообщает спецфразу
  #### Данные: api
  #### Как тестировать: 
  #### 1. Мокнуть ednpoint возвращающий 500
  #### 2. Отправить PDF через бота
  #### 3. Проверить текст ответа бота при неработающим api
  #### Ожидаемый результат:
  #### бот отправляет заранее прописанную фразу и логирует ошибку.
  #### Автоматизация тестирования: python-telegram-bot + pytest
- **FR-SYS-07:** Бот отправляет заранее подготовленную фразу из набора для `4xx` (в зависимости от кода ошибки/типа ошибки).
  #### Тестирование этого требования будет проходить вместе с требованием FR-SYS-01
- **FR-SYS-08:** Отсутствие персистентного хранения истории запросов.  
  #### Цель: убедиться, что не сохраняются содержимое документов
  #### Как тестировать: 
  #### 1. Провести запросы с наименованниями документов
  #### 2. Проверка логов в них не должно быть содержимое документов
  #### Ожидаемый результат:
  #### Данные документов не сохраняются в сервисе
  #### Автоматизация тестирования: pytest

## 2. Тестирование нефункциональных требований (общие)

- **NFR-PERF-01:** Среднее время обработки одного документа на сервере ≤ 1 мин.  
- **NFR-THR-01:** Система должна выдерживать одновременную загрузку до 100 PDF/мин.  
  #### Цель: проверка системы на среднее время обработки и выдержку одновременной нагрузки.
  #### Как тестировать:   
  #### Нагрузочный прогон (например 1000 документов в течение нескольких прогонов)
  #### Ожидаемый результат: система соотвествует средней время обработки и выдерживает нагрузку
  #### Автоматизация тестирования:
- **NFR-SEC-01:** Передача файлов по HTTPS.
  #### Цель: Проверить, что все файлы передаются по HTTPS
  #### Как тестировать:  
  #### Автоматические тесты: curl requests http:// ; only https accepted.
  #### Автоматизация тестирования: pytest
- **NFR-SEC-02:** При использовании очередей сообщений данные должны быть защищены:
  1. Передача только по зашифрованному каналу (TLS 1.2+).  
  2. Сообщения на диске брокера должны храниться в зашифрованном виде.  
- **NFR-AUTH-01:** Бот-серверный канал аутентифицирован.  
- **NFR-LOG-01:** Логирование ошибок (без хранения содержимого документов).
  #### Цель: проверка логов при 4хх/5хх
  #### Как тестировать:  
  #### 1. Генерировать ошибки 4хх и 5хх
  #### 2. Проверка наличия логов 4хх и 5хх
  #### Ожидаемый результат: логи с содержимом об ошибках 4хх и 5хх
  #### Автоматизация тестирования: pytest

## 3. Тестирование Telegram-бота — функциональные требования

- **BOT-FR-01:** Принимает PDF файлы и подтверждает приём.  
- **BOT-FR-02:** Пересылает файл на HTTP endpoint (`multipart/form-data`).  
- **BOT-FR-03:** Обрабатывает коды ответа сервера:  
  - `2xx`: отправляет пользователю отформатированный JSON.  
  - `4xx`: отправляет заранее подготовленную фразу из набора (например `INVALID_FORMAT`, `FILE_TOO_LARGE`, `UNAUTHORIZED`).  
  - `5xx`: отправляет спецфразу (например `SERVICE_TEMPORARILY_UNAVAILABLE`).  
- **BOT-FR-04:** Поддерживает команды `/start`, `/help`.  
  #### Цель: проверить, что бот поддерживает команды /start и /help.
  #### Как тестировать:
  #### 1. Отправка запросов в чат /start и /help
  #### 2. Проверка на соотвествие содержимого сообщений /start и /help
  #### Ожидаемый результат:
  #### Бот реагирует должным образом на соотвествующие запросы в чат /start и /help
  #### Автоматизация тестирования: python-telegram-bot + pytest
