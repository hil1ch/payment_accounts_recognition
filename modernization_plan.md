## 🏗️ АРХИТЕКТУРА ДЛЯ СМЕНЫ МОДЕЛЕЙ (OCR и LLM)

### Проблема
Сейчас модели OCR (EasyOCR) и LLM (Ollama) жестко зашиты в код. При смене модели нужно переписывать код.

### Решение: Strategy Pattern + Factory Pattern + Dependency Injection

### Структура

```
ml/app/
├── core/
│   └── config.py  # Конфигурация моделей
├── models/
│   ├── __init__.py
│   ├── base/
│   │   ├── __init__.py
│   │   ├── ocr_model.py      # Базовый интерфейс для OCR
│   │   └── llm_model.py       # Базовый интерфейс для LLM
│   ├── ocr/
│   │   ├── __init__.py
│   │   ├── easyocr_model.py  # Реализация EasyOCR
│   │   └── tesseract_model.py # Реализация Tesseract (пример)
│   ├── llm/
│   │   ├── __init__.py
│   │   ├── ollama_model.py   # Реализация Ollama
│   │   └── openai_model.py   # Реализация OpenAI (пример)
│   └── factory.py            # Фабрика для создания моделей
└── services/
    └── model.py              # Использует модели через интерфейсы
```

### Как это должно работать

#### 1. Базовые интерфейсы (абстрактные классы)

**`base/ocr_model.py`:**
- Абстрактный класс `OCRModel` с методом `extract_text(image_path: str) -> str`
- Все OCR модели должны реализовывать этот интерфейс
- Метод принимает путь к изображению, возвращает текст

**`base/llm_model.py`:**
- Абстрактный класс `LLMModel` с методом `generate(prompt: str, **kwargs) -> dict`
- Все LLM модели должны реализовывать этот интерфейс
- Метод принимает промпт и опции, возвращает результат генерации

#### 2. Конкретные реализации

**`ocr/easyocr_model.py`:**
- Класс `EasyOCRModel(OCRModel)` - обертка над EasyOCR
- В `__init__` инициализирует EasyOCR reader
- Реализует `extract_text()` используя EasyOCR

**`llm/ollama_model.py`:**
- Класс `OllamaModel(LLMModel)` - обертка над Ollama
- В `__init__` принимает URL Ollama, имя модели
- Реализует `generate()` используя Ollama API

#### 3. Фабрика моделей

**`models/factory.py`:**
- Функция `create_ocr_model(config: dict) -> OCRModel`
  - Читает из конфига тип OCR модели (easyocr, tesseract и т.д.)
  - Создает нужную реализацию
  - Возвращает объект через базовый интерфейс

- Функция `create_llm_model(config: dict) -> LLMModel`
  - Читает из конфига тип LLM модели (ollama, openai и т.д.)
  - Создает нужную реализацию
  - Возвращает объект через базовый интерфейс

#### 4. Конфигурация

**`core/config.py`:**
- Добавить настройки моделей:
  ```python
  ocr_type: str = "easyocr"  # или "tesseract"
  ocr_languages: list = ["en", "ru"]
  
  llm_type: str = "ollama"  # или "openai"
  llm_model_name: str = "gemma3:4b-it-qat"
  ollama_host: str = "http://ollama:11434"
  ```

#### 5. Использование в сервисе

**`services/model.py`:**
- В начале файла (или в отдельной функции инициализации):
  ```python
  ocr_model = create_ocr_model(settings.ocr_config)
  llm_model = create_llm_model(settings.llm_config)
  ```
- В `process_file()` использовать модели через интерфейсы:
  ```python
  text = ocr_model.extract_text(jpg_path)
  result = llm_model.generate(prompt)
  ```

### Преимущества такой архитектуры

1. **Легкая смена моделей:** Меняешь только конфиг, код не трогаешь
2. **Тестирование:** Можно подменить модели на моки для тестов
3. **Расширяемость:** Добавил новую модель = добавил новый класс, обновил фабрику
4. **Изоляция:** Проблемы с одной моделью не влияют на другую
5. **A/B тестирование:** Можно легко переключаться между моделями

### Когда это делать

**Этап 2.5 (после обработки ошибок, перед стабильностью):**
- Это рефакторинг, не критично для работы
- Но очень полезно для экспериментов с моделями
- Можно делать параллельно с улучшением качества кода

### Детальное описание компонентов

#### Базовый интерфейс OCR

**Что должно быть:**
- Абстрактный класс с методом `extract_text(image_path: str) -> str`
- Метод `__init__` принимает конфигурацию (языки, параметры)
- Опционально: метод `supports_format(file_path: str) -> bool` для проверки формата
- Опционально: метод `cleanup()` для освобождения ресурсов

**Пример использования:**
```python
ocr = EasyOCRModel(languages=["en", "ru"])
text = ocr.extract_text("image.jpg")
```

#### Базовый интерфейс LLM

**Что должно быть:**
- Абстрактный класс с методом `generate(prompt: str, **kwargs) -> dict`
- Метод должен возвращать словарь с ключами:
  - `result_text: str` - сгенерированный текст
  - `generated_time: float` - время генерации
  - Опционально: `tokens_used: int`, `model_name: str`
- Метод `__init__` принимает конфигурацию (URL, имя модели, параметры)
- Опционально: метод `stream_generate()` для стриминга

**Пример использования:**
```python
llm = OllamaModel(host="http://ollama:11434", model_name="gemma3:4b-it-qat")
result = llm.generate(prompt, temperature=0.1, max_tokens=1000)
```

#### Фабрика моделей

**Что должно быть:**
- Функция `create_ocr_model(config: OCRConfig) -> OCRModel`
  - Принимает конфиг с типом модели и параметрами
  - Использует match/case или if/elif для выбора реализации
  - Создает и возвращает нужную модель
  - Может выбрасывать исключение если тип модели неизвестен

- Функция `create_llm_model(config: LLMConfig) -> LLMModel`
  - Аналогично OCR

**Пример конфига:**
```python
ocr_config = {
    "type": "easyocr",
    "languages": ["en", "ru"],
    "gpu": False
}

llm_config = {
    "type": "ollama",
    "host": "http://ollama:11434",
    "model_name": "gemma3:4b-it-qat",
    "max_generation_time": 200
}
```

#### Регистрация моделей

**Вариант 1: Простой (if/elif в фабрике)**
- В фабрике просто проверяешь тип и создаешь нужную модель
- Просто, но при добавлении новой модели нужно менять фабрику

**Вариант 2: Регистрация (более гибкий)**
- Создать словарь `MODEL_REGISTRY = {"easyocr": EasyOCRModel, "ollama": OllamaModel}`
- В фабрике просто берешь класс из реестра и создаешь
- При добавлении новой модели - просто добавляешь в реестр

### План внедрения

1. **Создать базовые интерфейсы**
   - `base/ocr_model.py` с абстрактным классом
   - `base/llm_model.py` с абстрактным классом
   - Использовать `abc.ABC` и `@abstractmethod` для строгости

2. **Обернуть текущие модели**
   - Создать `ocr/easyocr_model.py` - обертка над текущим EasyOCR кодом
   - Создать `llm/ollama_model.py` - обертка над текущим Ollama кодом
   - Перенести логику из `model.py` в эти классы

3. **Создать фабрику**
   - `models/factory.py` с функциями создания моделей
   - Читать тип из конфига

4. **Обновить конфиг**
   - Добавить настройки моделей в `core/config.py`
   - Создать отдельные классы конфигов `OCRConfig`, `LLMConfig` или просто словари

5. **Обновить `model.py`**
   - В начале файла создать модели через фабрику
   - Использовать модели через интерфейсы в `process_file()`
   - Убрать прямой вызов EasyOCR и Ollama

6. **Протестировать**
   - Убедиться что все работает как раньше
   - Проверить что можно менять модели через конфиг

7. **Добавить новую модель (пример)**
   - Создать `ocr/tesseract_model.py` с классом `TesseractModel(OCRModel)`
   - Реализовать `extract_text()`
   - Добавить в фабрику или реестр
   - Теперь можно использовать через конфиг: `ocr_type: "tesseract"`

### Дополнительные улучшения (опционально)

1. **Кэширование моделей**
   - Модели могут быть тяжелыми для инициализации
   - Можно кэшировать созданные модели (singleton pattern)
   - Или использовать connection pool для моделей

2. **Валидация конфига**
   - Использовать Pydantic для валидации конфигурации моделей
   - Проверять что указанные модели существуют
   - Проверять что параметры корректны

3. **Логирование использования моделей**
   - Логировать какая модель используется
   - Логировать время работы моделей
   - Логировать ошибки моделей

4. **Fallback механизм**
   - Если основная модель недоступна, использовать резервную
   - Например: если Ollama недоступен, использовать OpenAI

5. **A/B тестирование**
   - Можно запускать несколько моделей параллельно
   - Сравнивать результаты
   - Выбирать лучшую
